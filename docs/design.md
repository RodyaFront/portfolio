# Стиль сайта

Принцип: **максимум грамотного UX, минимум бесполезного UI.**

Сайт - инструмент. Человек за минуту понимает, кто это, что сделано, и как написать. Всё, что этому не помогает, не рисуем. Это не запрет на дизайн: бесполезный UI - шум, а не сам визуал.

---

## Зачем страница

Порядок задач, сверху вниз:

1. Имя, роль, где находится.
2. Коротко, чем отличается (ownership, Vue/Nuxt, ещё и дизайн).
3. Работы: одна полка Portfolio, на карточках бадж Code and design / Code / Design.
4. Контакт - всегда на расстоянии одного действия.

Если блок не двигает по этому пути - его нет.

---

## Делать

- Одна колонка, предсказуемый ритм, много воздуха через отступы, не через декор.
- Типографика и иерархия вместо карточек, теней, градиентов и «атмосферы».
- Реальные ссылки: live, GitHub, Dribbble, Telegram, email.
- Картинки только там, где это сама работа (скрин продукта, шот с Dribbble).
- Состояния: hover/focus/visited/active, клавиатура, нормальный контраст, нормальный размер тапа. Общий press: hover чуть scale + tint (у фото ink-wash), active чуть продавливание. У очевидных кнопок 2px outline всегда есть (в покое прозрачный) и на press красится в оттенок темнее фона кнопки. Текстовые ссылки - цвет и underline, без scale.
- Быстрая загрузка: статика, свои картинки, без лишних шрифтов и библиотек «для красоты».
- Ключевые технологии в тексте - через `TechText` (иконка прямо перед словом в предложении). Реестр: `app/data/tech.ts`. Отдельный ряд чипов не использовать, если технологии уже названы в тексте.

## Не делать

- Зерно, блики, бесконечные бегущие строки, fake-stats, Lottie «чтобы живо».
- Модалки, если хватает страницы, якоря или внешней ссылки.
- Стеклянные шапки, градиентные кнопки, декоративная сетка.
- Копировать эстетику Dribbble-шотов на сам сайт: шоты - артефакты, оболочка - нейтральная.
- Чужой IP, выдуманные кейсы, «рекламный» тон из первого прототипа.
- Непрошеный редизайн всего шелла.

Движение - только если поясняет (фокус, скролл к секции). Не для вау.

## Как это выглядит на практике

Сдержанный документ: светлый или почти бумажный фон, один акцентный цвет для ссылок и текущего состояния, системная или одна читаемая гарнитура.

Полки работ - список, а не галерея ради галереи. У каждого кейса: бадж вида работы, название, что это, роль, стек, одна ссылка или один кадр. Visual-only UI - те же карточки с баджем Design, без подложек и ноутбучных мокапов поверх мокапов, если исходник уже в кадре.

Шапка короткая: имя, якоря, контакт. Подвал не дублирует полстраницы.

**Hero** - тезис страницы (кто / чем отличается / куда писать), не отдельный маркетинговый экран на весь вьюпорт.

## Статус

Сделано на странице:

- Одноколоночный шелл, токены paper / ink / accent, системная гарнитура
- Skip-link, шапка (имя, якоря полок, Telegram), подвал только с именем
- Hero: локация, имя, роль, тезис, availability, часы EET, бенто действий
- TechText: инлайн-логотипы Vue / Nuxt / TypeScript и тултипы с сорсом
- Контакт: email, Telegram, GitHub, LinkedIn, Dribbble
